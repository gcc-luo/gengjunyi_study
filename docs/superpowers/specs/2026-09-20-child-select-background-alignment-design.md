# 儿童端入口卡片与背景装饰对齐设计

## 状态

已确认方案 A：单个孩子时，入口卡片与前景绿色小山共享同一个视觉中心。

## 背景与问题

儿童端选择孩子页面的入口卡片位于内容网格的第一列，而背景装饰中的前景绿色小山通过固定的 `right` 偏移定位在页面右侧。只有一个可用孩子时，卡片的视觉中心在左侧、山丘的视觉中心在右侧，用户会感觉卡片与背景错位，像是卡片脱离了场景。

这个问题只影响选择孩子页面的视觉构图，不改变孩子选择、跳转、家长入口或多孩子布局的业务行为。

## 目标

1. 只有一个启用孩子时，入口卡片和前景绿色小山的视觉中心重合，卡片居中展示。
2. 两个或更多启用孩子时，继续使用现有两列卡片布局，背景装饰保持自然铺满，不因单卡规则破坏多卡页面。
3. 不改变卡片点击、加载禁用、错误提示和路由行为。
4. 在儿童端 390px 画布和桌面端包裹视图下保持稳定，不产生横向滚动。

## 设计方案

### 单个孩子

`SelectChildPage` 根据启用孩子数量为卡片网格增加单卡状态类。单卡状态下：

- 网格只保留一个居中的列，卡片使用受控宽度，保留入口卡片的轻量感。
- 前景绿色小山切换到相对选择页面内容区域的水平中心，而不是继续使用右侧固定偏移。
- 后景浅绿色小山仍保留左侧延展，作为背景层次，不要求与入口卡片中心完全重合。
- 卡片层级保持在山丘之上，家长入口保持页面中心对齐。

### 多个孩子

不增加单卡状态类，继续使用现有两列网格。前、后景山丘维持当前横向铺陈，两个卡片保持现有间距和宽度。

### 响应式与可访问性

- 使用 CSS Grid 与现有内容宽度，不引入固定视口宽度或 JavaScript 测量。
- 状态类由 React 根据真实启用孩子数量生成，避免依赖 `:has()` 等选择器。
- 继续保留按钮的键盘焦点样式、禁用状态和现有 `aria-label`。

## 代码范围

- `src/features/child/SelectChildPage.tsx`：为选择孩子网格增加单卡状态类。
- `src/styles/global.css`：新增单卡网格与单卡背景定位规则；保留多孩子现有规则。
- `src/features/child/ChildPages.test.tsx`：覆盖单卡状态类和多卡布局状态，防止后续样式条件回归。

不修改播放器、数据接口、路由、数据库或上传流程。

## 验收标准

- 仅有一个启用孩子时，入口卡片位于选择页内容的水平中心，绿色前景山丘最高区域位于卡片下方或与卡片同一中心轴附近，不再明显偏向右侧。
- 有两个启用孩子时，两个入口卡片仍为两列并排，间距和尺寸不发生明显回归。
- 选择任意卡片仍能进入 `/child/home`；选择过程中按钮仍会禁用；错误提示仍能显示。
- 单元测试和生产构建通过。
- 浏览器检查 390px 儿童端视口时无横向滚动，桌面端包裹视图中的卡片与背景关系一致。

## 测试策略

先在 `ChildPages.test.tsx` 增加单卡场景的失败断言，确认当前实现没有单卡状态类；再用最小 JSX/CSS 修改使断言通过。随后运行儿童端测试、全量测试和生产构建，并用浏览器分别检查单孩子与多孩子页面。
